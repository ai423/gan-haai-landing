# מערכת ההזדמנויות של קבוצת אמן

מערכת מודיעין מכירות חוצת-קבוצה: היא בונה את מפת חברות הבת, השירותים והלקוחות של קבוצת אמן מחשוב,
סורקת את הרשת אחת לחודש אחרי סימני רכישה אצל הלקוחות, מצליבה בין הכול, ומייצרת סיכום למנכ"ל
בפורמט: **חברת בת X עובדת עם לקוח Y — אפשר להציע לה גם את שירות Z, כי [סיבה עם ראיה וקישור]**.

---

## התקנה והרצה

```bash
cd aman-opportunity-system
npm install
cp .env.example .env         # והזינו ANTHROPIC_API_KEY
npm run db:reset             # יוצר בסיס נתונים וזורע נתוני פתיחה
npm start                    # http://localhost:3000
```

דרישות: Node.js 20 ומעלה. בסיס הנתונים הוא קובץ SQLite יחיד ב-`data/aman.db` — קל לגבות, קל להעביר.

### מפתח ה-API

המחקר, הסריקה וכתיבת הדוח משתמשים ב-Claude. השיגו מפתח ב-<https://console.anthropic.com/settings/keys>
והוסיפו אותו ל-`.env`:

```
ANTHROPIC_API_KEY=sk-ant-...
```

**בלי מפתח המערכת עדיין עובדת חלקית:** מנוע ההצלבה, כל ניהול המאגר והדוח הדטרמיניסטי פועלים.
מה שלא יעבוד: סריקת האתרים, המחקר החודשי, וכתיבת הדוח בשפה חופשית.

### לראות את המערכת עובדת מיד

```bash
node src/db/demo-signals.js   # טוען 12 אותות הדגמה (מסומנים "[הדגמה]")
npm run match                 # מייצר מהם הזדמנויות
npm run report                # מייצר דוח
node src/db/demo-signals.js --clear   # ניקוי
```

## פריסה לאוויר (Render / Railway)

המערכת היא שרת שרץ ברציפות עם בסיס נתונים שנשמר — לכן היא צריכה פלטפורמה שמריצה תהליך
ארוך עם נפח קבוע. **Vercel לא מתאימה** (פונקציות קצרות, דיסק שנמחק, בלי תהליך רקע).

### Render — הדרך הקצרה

הריפו כולל `render.yaml` מוכן. בדשבורד: **New → Blueprint → בחירת הריפו**.
Render יקרא את הקובץ ויקים את השירות עם נפח קבוע ובדיקת חיים. נשאר רק להזין שני משתנים
בדשבורד (הם מסומנים `sync: false` בכוונה כדי שלא יישמרו בקוד):

| משתנה | ערך |
|---|---|
| `ANTHROPIC_API_KEY` | המפתח מ-console.anthropic.com |
| `APP_PASSWORD` | סיסמה שתבחרו לכניסה למערכת |

### Railway

**New Project → Deploy from GitHub repo**, ואז בהגדרות השירות:

1. **Root Directory:** `aman-opportunity-system`
2. **Volume:** צרו נפח וחברו אותו ל-`/data`
3. **Variables:** הוסיפו את המשתנים מהטבלה למטה

הבנייה נעשית מה-`Dockerfile` שבתיקייה, לפי `railway.json`.

### משתני סביבה בפריסה

| משתנה | ערך | הערה |
|---|---|---|
| `ANTHROPIC_API_KEY` | `sk-ant-...` | חובה למחקר ולסריקה |
| `APP_PASSWORD` | סיסמה חזקה | **חובה** — בלעדיה השרת מסרב לעלות בייצור |
| `APP_USER` | `aman` | שם המשתמש לכניסה |
| `AMAN_DB_PATH` | `/data/aman.db` | חייב להצביע על הנפח הקבוע |
| `TZ` | `Asia/Jerusalem` | |
| `RESEARCH_CRON` | `0 3 1 * *` | ה-1 בכל חודש, 03:00 |
| `ENABLE_SCHEDULER` | `true` | |
| `NODE_ENV` | `production` | |

### אבטחה

- כל המערכת מוגנת בסיסמה (HTTP Basic Auth). רק `/healthz` פתוח, והוא מחזיר `{"status":"ok"}` בלבד.
- **השרת מסרב לעלות בסביבת ייצור בלי `APP_PASSWORD`.** זו הגנה מכוונת: המאגר מכיל את רשימת
  הלקוחות של הקבוצה, ומפתח ה-API חשוף לשריפת מכסה. לעקיפה מודעת (למשל מאחורי VPN ארגוני):
  `ALLOW_NO_AUTH=true`.
- המפתח והסיסמה נשמרים רק במשתני הסביבה של הפלטפורמה — לעולם לא בקוד ולא ב-git.
- כשהמערכת באוויר, החליפו את הסיסמה מדי פעם והגבילו את מכסת ה-API בקונסולה של Anthropic.

### גיבוי

בסיס הנתונים הוא קובץ יחיד. גיבוי מלא זמין גם מהממשק: **דוחות → ייצוא כל הנתונים (JSON)**,
או `GET /api/export`.

## מה המערכת עושה

### 1. מפת הקבוצה — חברות בת ושירותים

```bash
npm run scrape:group
```

סורקת את `https://www.aman-global.com/`, מזהה את עמודי החברות, אוספת את הקישורים היוצאים,
ומבקשת מ-Claude להבחין בין חברות בת לבין ספקים, שותפים ולקוחות. לכל חברה שנמצאה היא נכנסת לאתר
שלה ומחלצת את קטלוג השירותים.

המאגר מגיע כבר זרוע ב-14 חברות בת ו-48 שירותים שנאספו ממקורות פומביים (`src/db/seed-data.js`),
כדי שיהיה ממה להתחיל. הסריקה מעדכנת ומדייקת אותם — **ולעולם לא דורסת רשומה שנערכה ידנית**.

### 2. טריגרים — סימני רכישה

קטלוג של 22 סוגי טריגרים בחמש קטגוריות (פיננסי, ארגוני, טכנולוגי, רגולטורי, שוק): גיוס הון,
מיזוג ורכישה, מינוי CIO/CTO, אירוע סייבר, מעבר לענן, יוזמת AI, החלפת ERP/CRM, מכרז, משבר שירות ועוד.
לכל טריגר יש משקל בסיס, מילות מפתח לזיהוי, ו**תוקף בימים** — כמה זמן האירוע נשאר רלוונטי.

מעל זה יושבים 62 **מיפויים**: לכל חברת בת, אילו טריגרים מנבאים צורך באיזה שירות שלה, באיזה משקל,
ומה ההנמקה. למשל:

> אירוע סייבר → אמן סייבר וענן → גיבוי ושחזור, משקל 0.9
> «אחרי מתקפת כופר, גיבוי ו-DR הופכים לסעיף הראשון בתקציב.»

הכול ניתן לעריכה מהממשק, בעמוד של כל חברת בת.

### 3. לקוחות — כולל לקוחות משותפים

```bash
npm run scrape:clients
```

נכנסת לאתר של כל חברת בת, מאתרת את עמודי הלקוחות ומקרי הבוחן, מחלצת שמות מלוגואים
(alt, title, שם הקובץ) ומטקסט, ומסננת ספקים ופרסים.

**לקוח שמופיע אצל כמה חברות בת נשמר פעם אחת עם כמה קשרים** — הזיהוי נעשה לפי שם מנורמל,
שמות חלופיים ודומיין. זה בדיוק מה שמאפשר לזהות "הקבוצה כבר בפנים דרך חברה אחרת".

### 4. עריכה ידנית וייבוא

כל ישות במערכת — חברת בת, שירות, לקוח, קשר, טריגר, מיפוי, אות והזדמנות — ניתנת ליצירה,
עריכה ומחיקה מהממשק. בנוסף:

- **ייבוא מרשימה** — הדבקת שורות או CSV (`שם, ענף, אתר`), עם בדיקה מקדימה לפני שמירה.
  לקוח שכבר קיים מזוהה ולא משוכפל.
- **מיזוג כפילויות** — `POST /api/clients/:id/merge` מעביר קשרים, אותות והזדמנויות ללקוח היעד.
- **יומן שינויים** — כל יצירה, עדכון ומחיקה נרשמים ב-`audit_log` עם המצב לפני ואחרי.

לכל רשומה יש `origin` (זריעה / סריקה / ידני / ייבוא / מחקר) — ורשומה שסומנה `manual`
מוגנת מפני דריסה בסריקות הבאות.

### 5. מחקר חודשי על הלקוחות

```bash
npm run research                    # כל הלקוחות
npm run research -- --stale=25      # רק מי שלא נבדק 25 יום
npm run research -- --clients=3,7   # לקוחות ספציפיים
```

לכל לקוח מורצות שתי קריאות:

1. **חיפוש** — Claude עם כלי חיפוש הווב המובנה, מכוון לעיתונות הכלכלית (גלובס, כלכליסט,
   TheMarker), לעיתונות הטכנולוגית (אנשים ומחשבים, Geektime, CTech), לדיווחי בורסה
   (מאי"ה/TASE, דוחות רבעוניים), לאתר החברה ולמינויי בכירים.
2. **מבנה** — הפיכת הממצאים לרשומות `signals` עם קוד טריגר, ציטוט, קישור, מקור, תאריך ועוצמה.

**אות בלי כתובת מקור לא נכנס למאגר.** זו ההגנה המרכזית מפני המצאות. בנוסף כל אות מקבל
טביעת אצבע, כך שהרצות חוזרות לא מייצרות כפילויות.

המחקר גם מעשיר את פרופיל הלקוח (ענף, ציבורית/פרטית, סימול, גודל) — שוב, בלי לדרוס שדות ידניים.

### 6. הצלבה → הזדמנויות

```bash
npm run match
```

המנוע **דטרמיניסטי לחלוטין, בלי LLM** — מהיר, חינם, וכל ציון ניתן לפירוק:

```
ציון = 100 × משקל_המיפוי × עוצמת_האות × טריות × חום_הקשר × משקל_בסיס_הטריגר
       + בונוס קורוברציה (עד 15 נקודות על טריגרים שונים שמצביעים לאותו כיוון)
```

- **טריות** — דעיכה לפי גיל האות ביחס לתוקף של סוג הטריגר.
- **חום הקשר** — 1.0 אם חברת הבת כבר לקוח (`upsell`), 0.85 אם חברת בת אחרת בקבוצה כבר בפנים
  (`cross_sell` — יש דלת פתוחה), 0.45 אם הלקוח חדש לגמרי (`new_logo`).

לכל הזדמנות נשמרים: משפט ההנמקה, עד 4 ראיות עם קישורים, פירוק הציון, ורשימת חברות הבת
שדרכן אפשר לקבל היכרות. הזדמנות שאיבדה את הראיה שלה נמחקת בהרצה הבאה — אלא אם מישהו כבר נגע
בסטטוס שלה.

### 7. סיכום למנכ"ל

```bash
npm run report
npm run report -- --no-ai      # דטרמיניסטי בלבד
```

הדוח נבנה בשני שלבים: קודם נבנה דוח דטרמיניסטי מלא מהנתונים, ואז Claude כותב מעליו סיכום
מנהלים — שורה תחתונה, ההזדמנויות המובילות עם צעד מעשי, לקוחות משותפים ושטח לבן, מה לעשות
החודש, והסתייגויות. הדוח הדטרמיניסטי נשמר כנספח מתקפל, כך שתמיד אפשר לראות מאיפה כל טענה הגיעה.

אם קריאת ה-AI נכשלת — נשמר הדוח הדטרמיניסטי. הדוח אף פעם לא נכשל לגמרי.

### 8. תזמון

התזמון החודשי עולה עם השרת ומריץ את הצינור המלא (מחקר → הצלבה → דוח):

```
RESEARCH_CRON=0 3 1 * *      # ה-1 בכל חודש, 03:00
TZ=Asia/Jerusalem
ENABLE_SCHEDULER=true
```

הרצה ידנית זמינה תמיד — מכפתור בממשק (עמוד «הרצות ותזמון») או מ-`npm run pipeline`.
כל הרצה נרשמת עם סטטוס, ספירות, שימוש בטוקנים ויומן מלא.

## מגבלות שכדאי להכיר

- **הנתונים הזרועים הם נקודת פתיחה, לא אמת.** הם נאספו ממקורות פומביים ולא מסריקה ישירה של
  אתר הקבוצה. לכל רשומה יש `source_url` ו-`confidence`. הריצו `npm run scrape:group` ו-`scrape:clients`
  כדי להחליף אותם בנתונים מהאתרים עצמם, ועברו על מה שיצא.
- **הסורק תלוי במבנה האתר.** אתרים שנבנים כולם ב-JavaScript בצד הלקוח לא ייסרקו במלואם.
  במקרה כזה עדיף ייבוא ידני מרשימה.
- **המערכת מכבדת `robots.txt`** ומשהה בין בקשות. אפשר לכבות עם `RESPECT_ROBOTS=false`,
  אבל לא מומלץ.
- **המחקר עולה כסף.** כל לקוח = שתי קריאות ל-Claude עם חיפוש ווב. מחקר על 100 לקוחות
  הוא הרצה משמעותית — התחילו עם `--limit=5` כדי לאמוד עלות.
- **אימות אנושי נדרש.** האותות מגיעים עם ציטוט וקישור בדיוק כדי שאפשר יהיה לבדוק אותם.
  לפני שדוח מגיע למנכ"ל, שווה לעבור על 3-5 ההזדמנויות המובילות ולוודא שהקישורים אומרים
  מה שהמערכת טוענת שהם אומרים.
